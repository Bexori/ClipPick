# 首页 UI 设计说明

本文档仅描述首页的 UI 设计与交互规范，不包含设置页、历史页或收藏页等其他页面。

## 1. 设计目标

首页是应用的核心工作台，目标不是展示信息，而是让用户高效完成以下流程：

1. 输入或粘贴视频链接
2. 解析内容并查看结果
3. 选择下载格式和字幕选项
4. 管理播放列表条目、收藏状态和下载任务

整体设计应体现桌面软件的专业感，强调清晰的信息层级、克制的视觉语言和低干扰交互。

## 2. 页面整体结构

首页采用单列工作流布局，页面内容居中，左右留有较明显边距。内容从上到下依次排列：

1. 链接解析入口
2. 状态反馈区域
3. 解析结果区域
4. 下载配置区域
5. 下载任务列表区域

这种结构的核心原则是“先输入，再解析，再操作，再执行”，符合桌面工具软件的使用习惯。

## 3. 顶部解析入口

顶部解析入口是首页最重要的首屏区域，承担“输入 + 触发解析”的核心功能。

### 3.1 布局

从左到右排列：

1. 链接输入框
2. 粘贴按钮
3. 解析按钮
4. 收藏按钮

输入框占据主要宽度，按钮固定在右侧，形成标准的工具栏式操作区。

### 3.2 输入框

输入框用于输入视频链接或播放列表链接。

- 支持 `Enter` 触发解析
- 支持清空
- 空链接时解析按钮应不可用或无效
- 输入框应保持较高可识别度，作为首要操作对象

### 3.3 粘贴按钮

粘贴按钮位于输入框右侧，作用是从剪贴板快速填入链接。

- 鼠标悬停时显示轻量提示
- 点击后只执行“读取剪贴板并填充输入框”
- 不弹出大窗口，不打断用户当前流程

### 3.4 解析按钮

解析按钮是页面的主按钮，负责发起内容解析。

- 视觉上应最突出
- 点击后进入加载状态
- 加载期间应禁用重复触发
- 成功后进入结果展示阶段

### 3.5 收藏按钮

收藏按钮用于将当前链接加入收藏或取消收藏。

- 仅在存在可收藏内容时可用
- 收藏状态应通过图标状态变化体现
- 不建议使用大面积高饱和强调色
- 作为次级操作，应弱于“解析”按钮

## 4. 平台支持提示

输入区下方可显示支持平台标签。

### 设计目的

该区域不是核心操作区，而是能力提示区，用于减少用户对“是否支持该平台”的疑问。

### 视觉规范

- 使用小型 badge 或标签
- 颜色浅、对比低
- 不参与交互
- 不应抢占主流程注意力

## 5. 状态反馈区

状态反馈区用于展示解析失败、复制失败等轻量错误信息。

### 5.1 错误提示

错误信息使用横条形式展示。

- 左侧显示警告图标
- 中间显示错误文本
- 右侧提供关闭按钮

### 5.2 设计原则

- 不使用弹窗打断用户流程
- 错误提示应出现在视线自然可见的位置
- 用户可手动关闭
- 错误区应保持轻量，不要过度夸张

## 6. 加载状态

解析过程中使用骨架屏，而不是空白等待。

### 6.1 骨架结构

骨架区域模拟最终结果布局：

- 左侧为缩略图占位
- 右侧为标题和信息占位
- 用几条灰色线段表示文本区域

### 6.2 体验目标

- 明确告诉用户系统正在工作
- 减少“页面卡住”的感觉
- 让等待状态和结果状态保持一致的空间结构

## 7. 播放列表模式

当解析结果属于播放列表时，首页进入播放列表浏览模式。

### 7.1 播放列表头部

播放列表头部应包含：

- 列表图标
- 列表标题
- 条目数量
- 复制列表链接按钮
- 收藏按钮
- 关闭列表按钮

### 7.2 交互逻辑

#### 复制列表链接

点击后复制当前播放列表 URL，成功后给出轻量提示。

#### 收藏/取消收藏

用于管理整个播放列表的收藏状态，收藏状态应通过图标变化体现。

#### 关闭列表

关闭后返回普通解析状态，不保留列表浏览内容。

### 7.3 列表项结构

每个条目采用一行式布局，建议顺序如下：

1. 左侧缩略图
2. 中间标题和元信息
3. 右侧复制按钮
4. 最右侧进入箭头

### 7.4 列表交互

- 整行可点击进入条目详情
- 鼠标悬停时背景轻微变化
- 复制按钮仅在 hover 时更明显
- 箭头用于提示条目可继续深入

## 8. 单视频模式

当解析结果为单视频时，页面展示视频信息块和下载配置块。

### 8.1 视频信息块

视频信息块采用横向布局：

- 左侧为视频封面
- 右侧为标题、作者、格式数量、简介和翻译入口

这是首页中最重要的信息展示区。

### 8.2 封面区域

- 固定宽度缩略图
- 右下角显示时长标签
- 加载失败时显示占位图标

### 8.3 标题区域

- 标题字号较大
- 最多显示两行
- 超出部分截断
- 目标是控制高度，不让标题撑破布局

### 8.4 元信息区域

标题下方显示作者和格式数量等辅助信息。

- 字号小于标题
- 颜色更弱
- 只承担信息补充作用

## 9. 简介与翻译区域

简介和翻译是首页内容理解中的关键区域，必须严格区分。

### 9.1 简介逻辑

简介默认显示预览内容。

- 用户点击“展开简介”后显示完整简介
- “展开简介”只影响简介本身
- 收起简介时，翻译不受影响

### 9.2 翻译逻辑

翻译结果是独立块，不应与简介混在一起。

- 翻译按钮用于发起翻译
- 翻译完成后显示翻译结果块
- 翻译块可单独展开或收起
- 翻译块的状态不依赖简介展开状态

### 9.3 展示原则

首页中的原文与译文应被视为两个平行信息层：

- 原文是“内容本体”
- 译文是“辅助内容”
- 两者不互相覆盖
- 两者不共享同一折叠状态

### 9.4 推荐交互表现

翻译结果块建议采用以下模式：

1. 默认显示翻译结果的全文或较完整内容
2. 提供“展开翻译 / 收起翻译”文字操作
3. 收起后仅保留短预览
4. 重新展开后恢复全文

这样可以避免译文显示太长时占用过多空间，同时保留快速回看的能力。

## 10. 下载配置区

下载配置区承担“内容确认后执行下载”的功能。

### 10.1 结构

主要内容包括：

1. 格式选择
2. 字幕选项
3. 下载按钮

### 10.2 格式选择

格式选择用于决定下载的视频或音频规格。

- 应放在下载配置区最上方
- 是下载前最关键的决策项
- 选择结果应清晰可见

### 10.3 字幕选项

如果存在字幕资源，则展示字幕相关开关和语言选择。

- 是否下载字幕
- 手动字幕
- 自动字幕
- 是否嵌入视频
- 语言选择

### 10.4 下载按钮

下载按钮是本区域的主操作按钮。

- 建议占据整行宽度
- 状态应明确
- 不应与次级选项混淆
- 下载前应校验格式是否选中

## 11. 下载任务列表

页面底部显示当前下载任务列表。

### 11.1 作用

- 显示任务已进入队列
- 展示下载进度、速度和剩余时间
- 提供重试等操作入口

### 11.2 设计定位

任务列表是“执行反馈区”，不是首页主视觉中心。

- 不应喧宾夺主
- 但必须持续可见
- 用于帮助用户判断下载是否正常进行

## 12. 视觉风格

### 12.1 总体气质

首页应呈现以下风格：

- 桌面软件
- 功能导向
- 专业、克制
- 不偏后台管理系统
- 不偏移动端应用

### 12.2 视觉元素

- 使用浅边框和留白分区
- 圆角适中，不要过大
- 阴影应弱化
- 状态提示应轻量
- 主按钮突出，次按钮收敛

### 12.3 颜色策略

- 主操作使用主题强调色
- 次级操作使用中性文字色
- 错误、收藏、状态提示使用低饱和表达
- 不建议使用大面积强渐变或高饱和色块

## 13. 交互节奏

首页的交互节奏应保持流畅、短路径：

1. 输入或粘贴链接
2. 点击解析
3. 查看加载状态
4. 查看解析结果
5. 展开简介或查看翻译
6. 选择格式和字幕
7. 点击下载
8. 在任务列表中观察进度

这个流程符合桌面工具的典型使用逻辑，目标是减少思考成本和重复操作成本。
